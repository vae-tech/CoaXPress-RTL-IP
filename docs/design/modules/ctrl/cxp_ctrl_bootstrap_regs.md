The `clr_*_i` inputs from the deleted `cxp_link_reset_ctrl` are gone; the bit is exported as a level (`ctl_connection_reset_active_o`) and clears only once the tx domain has echoed it (`conn_reset_done_i`) or on a timeout. StreamPacketSizeMax powers up at 0.

Inputs chosen from the tree: RTL `src/rtl/ctrl/cxp_ctrl_bootstrap_regs.sv` and `src/rtl/gen/cxp_regmap_pkg.sv`, both generated by `src/regmap/gen_regmap.py` from `src/regmap/cxp_regmap.yaml` (+ `cxp_util_pkg.sv`; generated register table `docs/design/modules/pkg/cxp_regmap.md`); unit TB `src/tb_unit/ctrl/cxp_ctrl_bootstrap_regs/`; integration TBs `src/tb_unit/top/cxp_interface_top/` and `src/tb_unit/top/cxp_device_top/`; spec CXP-001-2015 (CoaXPress 1.1.1) §10.3.1–10.3.41, Table 45, Table 22; regression `make -C src/tb_unit`; output `docs/design/modules/ctrl/cxp_ctrl_bootstrap_regs.md`.

Device-side bootstrap register file: a single-cycle register slave that serves the Table 45 map, the GenICam and XmlUrl strings, the §10.3.19–27 use-case features, nine named manufacturer registers and a GenICam XML ROM. It exports the control state and owns §10.3.28 ConnectionReset: it applies the register values, pulses the counter clears and holds the ConnectionReset bit until the other clock domains have applied their part.

- **Access codes.** Every access returns a Table 22 code on `err_o` with `ready_o`, decoded on all 32 address bits:

  | Code | When |
  |---|---|
  | 0x40 | `addr_i[1:0]` ≠ 0, or no register answers (bootstrap rows only at `addr_i[31:16]` = 0, so 0x0001_4000 is not ConnectionReset) |
  | 0x43 | write to an RO row, a 0x3000 slot, a string, the ZERO range or the XML ROM |
  | 0x44 | read of a write-only feature (`access: WO`): AcquisitionStart, AcquisitionStop |
  | 0x41 | write of a value the register refuses (`min`, `max`, `allowed`, `multiple`): XmlManifestSelector > 0; ConnectionReset > 1; StreamPacketSizeMax not a multiple of 4; ConnectionConfig ≠ 0x0001_0028; TestMode > 1; TestErrorCountSelector ≥ `p_NUM_LINKS`; Width or Height outside 1..4096; AcquisitionMode ≠ 0; PixelFormat outside 0x0101–0x0105 (Mono8 … Mono16); TapGeometry ≠ 0; Image1StreamID > 0xFF; FrameCount > 0xFFFF; TestPattern outside 0..3; OffsetX or OffsetY > 4095; SourceTag > 0xFFFF; StreamFlags > 0xFF; TpgRun > 1 |
  | 0x00 | otherwise |

  A refused write changes nothing and raises no strobe. A word of the manufacturer window without a named register still reads 0 and takes writes silently (OK).
- **Generated.** Addresses, reset values, ConnectionReset values, strings and ports come from `src/regmap/cxp_regmap.yaml`; `make regmap` regenerates the GenICam XML `src/regmap/genicam/cxp_camera.xml`, `cxp_regmap_pkg` (served strings included), the ROM image `src/rtl/gen/cxp_camera_xml.mem`, `src/model/cxp_protocol/cxp_protocol/regmap.py`, `src/regmap/cxp_regmap.h` and `docs/design/modules/pkg/cxp_regmap.md`; `make regmap-check` (in `make ci`) fails when any of them is stale. The XML size in `XML_BLOB_BYTES`/`XML_BLOB_WORDS` and the size token of the XmlUrl string are computed from `src/regmap/genicam/cxp_camera.xml`, so they no longer have to be kept in step by hand. The generator rejects unaligned addresses, bootstrap rows outside 16 bits, overlapping rows or slots, an alias on a named manufacturer word, strings longer than their field, an `allowed` list that is not on an RW row or leaves out the power-on value, `min` / `max` / `multiple` on a row that is not RW or ConnectionReset, and a `multiple` that is not a power of 2. It also fails when `src/regmap/genicam/cxp_camera.xml` disagrees with the YAML for a feature or a named manufacturer word: the XML's Min / Max against `min` / `max`, its enumeration entries against `allowed`, and its AccessMode (WO or not) against `access`.
- **Placement.** `cxp_device_top` instantiates it on `rx_clk` on the control plane's register bus (`reg_*`) and wires every side effect (see `cxp_device_top.md`). `tb_cxp_interface_top` and `src/verif/uvm/sv/tb_cxp_top.sv` instantiate it next to `cxp_interface_top` behind their own APB3 bridges, because their tests reach into it by hierarchy and inject APB faults.
- Implements §10.3.1–10.3.41 (Table 45) and the §10.3.28 side effects. `cxp_ctrl_bus_master` splits §10.3.2 multi-word accesses into single-word accesses upstream.

- **Reset.** `sys_rst_n` asserts asynchronously and is active low; nothing inside synchronises the deassertion. All flops are reset; `device_user_id_q` resets to a non-constant value (Medium 5). `xml_rom` is initialised only by `$readmemh`.
- **Clocking.** Single domain `sys_clk`, no CDC inside. In `cxp_device_top` and `src/verif/` it runs on `rx_clk`, the domain of `cxp_interface_top`'s register-bus and APB ports, configuration inputs, the ConnectionReset level and its echo, and the returned counters. With `p_ASYNC_CLOCKS` = 1 `cxp_interface_top` crosses all of them (`cxp_interface_top.md`), so the register file itself needs no synchroniser.
- **Outputs and flow control.** Every `ctl_*` output is a flop or a constant. There are no stalls and no wait states; `err_o` is the only error output.
- **Comments that no longer match.** `tb_cxp_interface_top.sv:290` calls `ready` "combinational on writes", but it is registered.

## How it works

1. **Read.** `rdata_c` is a combinational override chain (`cxp_ctrl_bootstrap_regs.sv:308`), and `rdata_o` captures it on `re_i`. When several sources hit, the later group wins:

   | Order | Hit | Source |
   |---|---|---|
   | 1 | `boot_hit` (`addr_i[31:16]` = 0) and `bus_addr` (= `addr_i[15:0]`) equals a bootstrap row (`hit_<row>`); the ZERO range adds no source | Constant for RO rows, the flop for RW rows, the selected counter input for CNT rows |
   | 2 | `bus_addr` in 0x20C0–0x20CF | `device_user_id_q` word |
   | 3 | `bus_addr` in one of the six string ranges (XmlUrl and five GenICam strings) | `pick_word(string, offset>>2)` |
   | 4 | `mfr_hit` (full `addr_i`) | the named register selected by `addr_i[5:2]`; 0 for a word without a named register |
   | 5 | `hit_<feature>`: `boot_hit` and `bus_addr` = its 0x30xx slot, or full `addr_i` = its alias | the feature flop |
   | 6 | `blob_hit` (full `addr_i`) | `xml_rom[blob_off >> 2]` |
2. **Access code and write.** `err_c` is combinational: 0x40 for `addr_i[1:0]` ≠ 0 or `!any_hit` (the OR of every row, feature, manufacturer and ROM hit), else 0x43 for a write with `ro_hit` (RO, STR and ZERO rows, the 0x3000 slots and `blob_hit`), else 0x44 for a read with `wo_hit` (AcquisitionStart, AcquisitionStop), else 0x41 for a write with `bad_val` (a `min`, `max`, `allowed` or `multiple` check fails on the hit register); `err_q` registers it with `ready_q`. `wr_ok = we_i & (err_c == 0)` feeds three gates: `wr_bs = wr_ok & !blob_hit & !mfr_hit` for bootstrap rows, `wr_dev = wr_ok & !blob_hit` for features, `wr_mfr = wr_ok & !(any feature hit)` for named manufacturer words. Under `wr_bs`: XmlManifestSelector, MasterHostConnectionID, StreamPacketSizeMax, ConnectionConfig (+ `connection_config_wr_q`), TestMode, TestErrorCountSelector, ElectricalComplianceTest, write 0 to 0x4024–0x4034 (`test_count_clr_q`), the DeviceUserID words (only the bytes `wstrb_i` enables, `merge_bytes`), and `crst_write = wr_bs & hit_connection_reset & wdata_i[0]`. RO rows have no write logic.
   Later statements in the same `always_ff` then override these: the ConnectionReset bit, then the ConnectionReset values on `crst_apply`.
3. **ConnectionReset bit.** `crst_apply = crst_write | conn_reset_req_i`. On that edge the bit (`reg_q[R_CONNECTION_RESET]`) is set, `crst_timer_q` loads L and `crst_tmo_q` loads T; `crst_pulse_q` pulses only for a host write. A second request reloads both counters. While the bit is set both count down to 0, and the bit clears on the edge where (`crst_timer_q` = 0 and `conn_reset_done_i` = 1) or `crst_tmo_q` = 0. So it lasts at least L+1 cycles, until the other domains have seen it, and at most T+1 cycles. The bit drives `ctl_connection_reset_active_o`; in `cxp_interface_top` it restarts the PacketTags, flushes the stream path, clears TestPacketCountTx and holds the device trigger de-asserted while it is high, and the tx copy returns as `conn_reset_done_i` once the flush is done (`cxp_interface_top.md` How it works 3).
4. **ConnectionReset values.** On the same `crst_apply` edge it clears XmlManifestSelector, MasterHostConnectionID, StreamPacketSizeMax, TestMode, TestErrorCountSelector and ElectricalComplianceTest to 0 and sets ConnectionConfig to `CONNECTION_CONFIG_CONN_RESET`; one cycle later (`crst_apply_q`) the three test-counter clears pulse once. The values are applied once per request, not held. It leaves the features, the manufacturer registers and DeviceUserID untouched. Power-up is a connection reset: every row's power-on value equals its ConnectionReset value (the generator enforces it), and the bit itself powers up at 0.

- Same-cycle rules:
  - `conn_reset_req_i` and a host write to a ConnectionReset register → the ConnectionReset value wins; `ctl_connection_config_wr_o` still pulses.
  - A host write of 1 to 0x4000 and `conn_reset_req_i` → one request: the values are applied once and the pulse fires.
  - A request while the bit is already set → both counters reload; the bit stays 1.
  - `we_i` and `re_i` in the same cycle → the write lands, and `rdata_o` returns the old value.
- Unaligned addresses get 0x40 and change nothing. A read still loads `rdata_o` with whatever the low-bit-blind string, DeviceUserID or manufacturer decode selects, but `cxp_ctrl_bus_master` stops on the error and returns no data.
- Latency and throughput: a read with `re_i` at edge N has `rdata_o` and `ready_o` valid after N (1 cycle), at 1 access per cycle. Writes update the register and `ctl_*` at N, and strobes are high for 1 cycle. ConnectionReset reads 1 for L+1 cycles when the echo is back by then (9 at L = 8 in the unit bench, whose echo is 3 cycles late); with `p_ASYNC_CLOCKS` = 1 the echo takes two `tx_clk` plus two `rx_clk` edges.
- Invariants that hold by construction but are not asserted: `ctl_connection_reset_pulse_o` ⇒ all three test-counter clears in the same cycle; bit = 0 ⇒ `crst_timer_q` = 0; `rdata_o` changes only on `re_i` edges. Asserted: the bit is never high for more than T+1 cycles after the last request (`cxp_conn_reset_sva`).

## Arbiter integration

There is no TX arbiter port. The module is a single-master register slave; the points below cover its bus and side-band behaviour.
- **Handshake.** In `cxp_device_top`, `we_i`/`re_i` = the register bus's one-cycle `reg_req` (qualified by `reg_we`) and the registered `ready_o` returns as `reg_ack` one cycle later. The two TB shells pulse `we_i`/`re_i` in the first APB ACCESS cycle, so `pready` rises in the second (SETUP + 2 ACCESS cycles per transfer).
- **Error path.** `cxp_device_top` wires `err_o` to the control plane's `reg_err`, so the code reaches the acknowledgment unchanged. `tb_cxp_interface_top` and `src/verif/uvm/sv/tb_cxp_top.sv` raise `pslverr` when `err_o` ≠ 0 (verif ORs in its injected fault); `cxp_ctrl_apb_bridge` then answers 0x40 whatever the code, because APB carries one error bit.
- **Host writes during the reset.** The ConnectionReset values are applied once, on the request edge, so a write made while the bit is still 1 is kept.
- **ConnectionReset path.** `ctl_connection_reset_active_o` drives `conn_reset_active` and `conn_reset_done` returns to `conn_reset_done_i` in `cxp_device_top` (and so in `src/emu/bridge`), `tb_cxp_interface_top` and `src/verif/uvm/sv/tb_cxp_top.sv`. In `cxp_device_top`, `ctl_connection_reset_pulse_o` also stops acquisition (ORed into `acq_stop`) and `conn_reset_req_i` is tied 0; `tb_cxp_interface_top` drives `conn_reset_req_i` from its `link_reset_req` input. The write gets one acknowledgment; the end of the reset sends none.
- **TX side band in `cxp_device_top`.** `ctl_test_mode_o` → `cfg_test_mode` suppresses the stream, trigger and I/O-ack ports. `ctl_stream_pkt_dsize_o` → `cfg_dsizeP`, as bytes of the whole packet, and `cfg_stream_en` = the register ≠ 0 (`cxp_device_top.md` How it works 2). `ctl_test_err_count_clr_o`, `ctl_test_pkt_tx_clr_o`, `ctl_test_pkt_rx_clr_o` → `clr_lt_err`, `clr_lt_pkt_tx`, `clr_lt_pkt_rx` (a ConnectionReset pulses all three). `ctl_connection_config_wr_o` → `conn_cfg_wr`, which restarts the stream PacketTags. OffsetX, OffsetY, SourceTag and Image1StreamID → the TPG image header (`cfg_xoffs`, `cfg_yoffs`, `cfg_srctag`, `cfg_streamid`).

## Verification

Verilator 5.046 with cocotb 2.0.1, built with `--assert`; `cxp_conn_reset_sva` is bound to this module (the bit clears within `p_CONN_RESET_TIMEOUT` + 1 cycles). No coverage is collected, because no TB registers an FSM with `fsm_coverage`. `make lint` is clean; the partial use of `blob_off` is waived in `src/rtl/cxp_ip.vlt`.

### Unit TB — `src/tb_unit/ctrl/cxp_ctrl_bootstrap_regs/`

The wrapper `tb_cxp_ctrl_bootstrap_regs_top` flattens the counters to link 0, sets `p_NUM_LINKS` = 1, L = 8 and T = 64, ties `wstrb_i` to 4'hF (whole-word writes only), exposes `conn_reset_req`, `ctl_connection_reset_active_o` and `conn_reset_done`, and leaves `ctl_test_pattern_o` open. `reset()` starts `echo_active`, which returns the active level on `conn_reset_done` three cycles later (as the tx domain would) unless a test withholds it. The Makefile packs `src/regmap/genicam/cxp_camera.xml` into `cxp_camera_xml.mem` in the TB directory before each run. The clock is 10 ns; `sys_rst_n` is held low for 4 edges, then 2 idle edges follow, with NV and counters at 0. `CxpRegBus` pulses `we`/`re` for 1 cycle, samples `rdata` and `err` (kept as `bus.err`) in ReadOnly and spaces operations 2 cycles apart. There are no shared checkers; all checks are inline asserts. The test file predates the generator and is unchanged by it.

## Known issues and recommendations

### Critical

1. **Resolved: the 0x3000 block held values instead of addresses.** Each slot is now an RO row that reads its feature's address in the manufacturer window (§10.3.19–27, Table 45: R); a write gets 0x43, and AcquisitionMode has the alias 0x1_0040 (`test_05_device_control_regs`).
2. **Resolved: two §10.3 side effects did not reach the datapath.** In `cxp_device_top`, `ctl_connection_config_wr_o` drives `conn_cfg_wr`, which restarts the stream PacketTags (§10.3.33), and `ctl_stream_pkt_dsize_o` is taken as bytes of the whole packet, with no stream while it reads 0 (`cxp_device_top.md` How it works 2). `tb_cxp_interface_top` and `src/verif/uvm/sv/tb_cxp_top.sv` wire the ConnectionConfig pulse too.
3. **The ConnectionReset pulse is not checked at unit level.** The reset itself now travels as `ctl_connection_reset_active_o`, which tests 22–24 check; the pulse only stops acquisition in `cxp_device_top`. The unit test still never sees the pulse high, so a stuck-at-0 pulse passes; `tb_cxp_interface_top` leaves it open.
   **Fix:** in `test_08_connection_reset_pulse_and_self_clear`, assert pulse == 1 at the write edge and 0 one cycle later. Effort: 15 min.

### Medium

1. **Resolved: TestErrorCountSelector was unbounded.** A write of a selector ≥ `p_NUM_LINKS` gets 0x41 and changes nothing (`max: links`, `test_21_test_err_sel_bound`).
2. **ConnectionConfig default is too coarse.** ConnectionReset restores 0x0001_0028, which §10.3.34 describes as the recommended mode, while §10.3.28/§10.3.33 require the discovery rate and one connection. **Fix:** a separate `conn_reset` value for ConnectionConfig in the YAML. Effort: 0.5 h.
3. **Resolved: StreamPacketSizeMax was 256 at power-up.** It powers up at 0, its ConnectionReset value (§10.3.28); `src/regmap/gen_regmap.py` refuses any row whose power-on value differs from its ConnectionReset value.
