How the emulator works

The emulator runs the whole CoaXPress 1.1.1 device IP as a camera that a real C++ host talks to. The host (src/emu/host) and the camera exchange framed 32-bit words over two Linux named pipes. The camera is either the RTL, simulated by Verilator behind a DPI-C bridge (src/emu/bridge), or the host's own in-process virtual camera. Both speak the same wire contract, so every CLI command, GUI view and validation case runs unchanged against either.

Host C++17 / Qt

  • libcxpcore: packet codecs, CRC, FIFO transport, stream parser, GenICam
  • cxp CLI: read, write, discover, stream-capture, trace, validate
  • cxp-gui: device explorer, image and statistics views, validation window
  • Validation campaign: 166 cases (139 runnable over the link)

Link two named pipes

  • cxp.h2c host → camera, cxp.c2h camera → host
  • Every frame is MAGIC | NWORDS | NWORDS×u32, little-endian
  • CXP1 word frames (SOP..EOP packets), CXC1 characters, CXB1 bench ops
  • Resync on an unknown magic, and the pipes reopen when a peer restarts

Camera RTL or virtual

  • RTL: cxp_hw_env.sv wraps cxp_device_top; three 10 ns clocks, run asynchronously
  • Uplink is real: 8B/10B symbols go onto rx_serial one bit at a time
  • Downlink is the parallel word bus cxp_if_data_o/kmask, sampled every tx_clk
  • vcam: cxp sim / --spawn-sim, fast, but it models the reference camera, not the standard
A register read, in one line: the host builds a Table 21 command → it is wrapped in a CXP1 frame on cxp.h2c → the DPI bridge 8B/10B-encodes it and shifts it into the RTL bit by bit → the RTL decodes it, reads the register and sends a Table 22 ack on its word bus → the bridge strips IDLE and wraps the SOP..EOP packet on cxp.c2h → the host checks its CRC and returns the value. The Transactions section steps through this with the real words from an RTL run.

Bench: what a lab wires besides the link

The PyUVM testbench drives more than the link: the trigger input, the pixel port, the extension-link strap, a faulting register bus and the host bit rate. The emulator gives the host the same control through CXB1 frames on the same pipes (protocol/bench.h). The bridge applies each op at once in bench_op(), and cxp_hw_env.sv polls the result every clock. A device without a bench skips CXB1 as garbage; when HELLO gets no answer, the host treats the device as having no bench.

A reply is the op code with bit 7 set (op | 0x80). This is why the protocol log prints the unsolicited events as BENCH op 0x92 (UPLINK_MARK) and 0x93 (FRAME_DL) around every control exchange.

Validation campaign

cxp validate and the GUI's validation window both drive the same validation::Campaign. make emu-rtl runs every runnable case against the RTL camera and gates the verdicts.

What a check can use

  • Context::exchange: a raw command, and its ack (--ack-timeout)
  • Register calls through the GenICam XML (--timeout)
  • sleepMs / record, multiplied by the timeout scale
  • iparam, ilist, spsmList: the case parameters
  • Bench ops and CXC1 character frames

Verdicts

PASSevery expectation held
FAILan expectation failed, or a plain access got no answer
NOT RUNthe case needs lab hardware or a missing capability
ERRORa host-side fault in the check
STOPPEDthe user stopped the run
Timing in a simulator. A host test packet crosses the serial uplink bit by bit, so the link-test cases get a timeout scale computed from their packet count (CT-004 runs at ×500). A spec limit that the check measures, such as --ack-latency, is never scaled. After each case the host reads Standard; when it gets no answer, the run reports which case left the device silent.

Run it

From the repo root

make emu-build # bridge (Verilator) + C++ host make emu-cli # RTL camera, `cxp discover --params` make emu-cli CMD="read 0x0000" make emu-cli CMD="write 0x10000 320" # Width make emu-cli DEV=vcam CMD="read 0x0000" # same, virtual camera make emu-gui # device explorer on the RTL make emu-cli WAVE=vcd # + build/cxp_hw_env.vcd make emu-rtl # validation campaign, gated (~25 min)

tools/run_emu.sh starts the camera on a private FIFO pair (/tmp/cxp_emu.XXXXXX), waits for camera RTL running and the pipes, runs the host, and stops the simulator on exit. The camera log goes to src/emu/host/build/emu_logs/camera_<dev>.log.

By hand, two terminals

# terminal 1: the camera (runs until Ctrl-C) make -C src/emu/bridge run FIFO_DIR=/tmp/cxp # TRACE=1 REGLOG=1 OPT_LEVEL=0 SIM=vsim # WIDTH=128 HEIGHT=64 PIXFMT=0x0101 # CXP_HW_DEBUG=1 per-frame stderr trace # terminal 2: the host cxp --fifo-dir /tmp/cxp --protocol-log p.log read 0x0000 cxp --fifo-dir /tmp/cxp stream-capture --frames 4 --out caps cxp --fifo-dir /tmp/cxp trace --pcap cxp.pcap --seconds 2 cxp --fifo-dir /tmp/cxp validate CT-004 BOOT-002 cxp-gui --fifo-dir /tmp/cxp
